# Kaldrivon MiniSMO 0.5.0 — Release Notes

Windows 11 x64. Installer: `Kaldrivon-MiniSMO-0.5.0-Setup.exe` (checksum in `.sha256`). 0.5.0 is the first public release; earlier builds were previews and no upgrade path from them is supported. Database schema 29.

The installer, the uninstaller and MiniSMO's programs are code-signed by Kaldrivon (Azure Artifact Signing, Public Trust); Windows shows the publisher when you run the installer. The `.sha256` file lets you check the download as well. The EULA is version 1.0 (effective 2026-10-20, licensor 1001742069 Ontario Inc. operating as Kaldrivon).

## Security hardening

This release went through a security review with free and open-source tools (see `security/` in the source). MiniSMO is not certified against any security standard. Changes:

- MiniSMO's local API (127.0.0.1:8765) now needs a key that is new at every start and known only to the MiniSMO window and to local tools of the same Windows user (`data\api.key`). Requests for another host name (DNS rebinding) and requests from web pages (Origin header) are refused. The window uses a backend only after it proves it holds the key. API documentation pages are no longer served in the installed app. See *Local API Protection* in Help.
- file-based PM sends file server credentials only to a confirmed server. SFTP host keys (the NF's own NETCONF host key is accepted on its address) and self-signed TLS certificates must be confirmed once on the FILE-BASED PM card (**TRUST…**, with the fingerprint); a changed identity stops retrieval. Plain `http://` downloads never carry credentials and redirects are not followed. **Changed behaviour:** a file server that was used before and is not the NF's own SSH server waits for confirmation once. Schema 27.
- the VES collector accepts events only from known NF addresses (each NF's address, what its host name resolves to, its Call Home address), this PC, and addresses or networks you allow in Settings. Other senders get 403, are counted and listed under **REFUSED SENDERS** on the VES Collector tab with **ALLOW…**. A recommendation is shown while *any address* is chosen.
- the VES collector is HTTPS only. The plain HTTP listener (8080) and the *Protocol NFs should use* setting are gone; the installer opens only 8443.
- CSV exports (alarms, inventory, PM, audit log, NETCONF log, reports, capacity) show a cell that starts with `=`, `+`, `-`, `@`, tab or CR as text (leading apostrophe), so a spreadsheet never runs a formula hidden in an alarm text or name. Plain numbers are unchanged.
- MiniSMO logs in to an NF only after its SSH host key is confirmed. The first **TEST CONNECTION** in *Add External NF* shows the fingerprint (nothing is sent yet); **CONFIRM HOST KEY** tests again with the credentials and SAVE stores the key. A saved NF without a confirmed key shows **Confirm the NF's SSH host key** with **CONFIRM HOST KEY…** on its Overview tab. *Lab only: trust the host key on the first connection* keeps the earlier behaviour per NF. See *Confirming the SSH Host Key* in Help. Schema 28.
- the VES collector limits open connections (64), drops silent connections after 30 s, runs each TLS handshake in its own connection thread (a client that connects and stays silent no longer holds up the listener), and allows each sender 100 requests per second (bursts of 500); more get 429 with Retry-After. The counters are on the VES Collector tab.
- the VES collector's TLS 1.2 offers only forward-secret AEAD suites (ECDHE with AES-GCM or ChaCha20-Poly1305); CBC suites are gone. TLS 1.3 is unchanged. An NF whose TLS stack has no AEAD suite cannot connect.
- the audit log is tamper-evident. Each entry stores a keyed hash chained to the previous one; **VERIFY LOG** on the Audit Log page reports *intact* or the first entry that was changed, inserted or removed outside MiniSMO. The CSV export includes each entry's hash. Schema 29.
- more secret values are masked in snapshots, backups, exports and logs: key-chain keys (`key-string`, `keystring`, `hexadecimal-string`, IOS XE and RFC 8177), cleartext keys (RFC 9640), routing-protocol authentication keys, and Authorization headers / API tokens in log lines.
- the release build installs the backend's runtime packages only from a hashed lock file (`requirements.lock`, every transitive package with SHA-256 hashes); a changed download stops the build. Dependency updates: starlette 1.7.0, python-multipart 0.0.32, cryptography 50.0.2 (known advisories fixed; pip-audit reports none).

Behaviour changes to know about:

- An NF that sends VES from an address other than the one in MiniSMO (NAT, separate management interface) is refused until you allow that address (**ALLOW…** on the VES Collector tab).
- NFs that can only send VES over plain HTTP cannot reach the collector; it is HTTPS only.
- Adding an NF asks you to confirm its SSH host key before MiniSMO logs in. *Lab only: trust the host key on the first connection* keeps the old behaviour for simulators.
- A file server used for measurement files that is not the NF's own SSH server is used only after you confirm its identity once.
- Local tools and scripts that call MiniSMO's API need the `X-MiniSMO-Key` header (key in `data\api.key`).

## New and changed

- **VES collector status, STOP and START** replace RESTART: the LISTENER card shows status, running since / stopped at, a self-test of each listener, the last request and this PC's addresses. A collector stopped by hand or failing the self-test raises the internal alarm *VES collector not listening*.
- VES collector resource protection: at most 4 requests store events at the same time; during an event storm further requests wait and then get `503 Retry-After` instead of exhausting the database connection pool (seen as "QueuePool limit … reached" in the log).
- VES Collector tab: the event time column was too narrow to read. Notifications window: long lines were cut off; they wrap now.
- **Capacity-only licensing.** All features included. Free for up to 5 external NFs. A paid license is required for additional external NFs. Removed: every Community feature restriction and quota (the daily allowance of former Pro features, item limits on rules / schedules / webhooks / tokens / templates / desired states, the READ-only and 1,000-requests-a-day limit of the northbound API, Pro-only settings), the PRO badges, Community notes, upgrade notices and disabled controls in the Windows app. Licenses already issued keep their capacity; signing keys, signature validation and activation are unchanged. Database schema 20 removes the old daily usage counters; items that were paused beyond the allowance run again.
- **One NF = one endpoint.** An external NF with the same address and port (case-insensitive name, canonical IP), or for Call Home the same SSH host key / serial number / hardware ID, as an NF already stored is refused as a duplicate (`DUPLICATE_NF`) on add and edit, so one device never takes two slots. Disconnecting or stopping monitoring never frees a slot; deleting does.
- **Northbound API security rate limits** (every edition, not licensing): 20 requests a second per token with bursts up to 40, and an address is blocked for 60 s after 10 failed authentications in a minute (`429 RATE_LIMITED`, `Retry-After`).
- **Edition names follow the price list**: Community (free, 5 external NFs), Small Deployment (commercial, up to the licensed number, 25), Unlimited (no numerical limit). The edition shown is decided by the capacity of the valid license, not by a name in the file. *Supported* is a support entitlement, not a license. The license generator defaults to Small Deployment.
- **Integration numbers and unlicensed (hidden) NFs.** Every external NF is numbered when it is integrated (schema 21; existing NFs are numbered in the order they were added). When more NFs are stored than the capacity allows (expiry, removal, a lower license, also while running), the oldest integrations stay managed and the newer ones are hidden: not connected, monitored or reported (lists, topology, dashboards, alarms, PM, reports, northbound API, R1, VES), with nothing deleted. The License page, title bar and Settings show how many. Installing a license brings them back, oldest first, up to the new capacity. When a slot is free, ADD EXTERNAL NF first offers to BRING BACK a hidden NF. *Settings > Unlicensed NFs > DE-INTEGRATE ALL HIDDEN NFS…* removes them (confirmed, with progress; MiniSMO's own VES subscription is removed first).
- **A DNS name and an IP address of the same NF are one NF**: names are resolved when an NF is added or edited (and refreshed in the background), and an overlap of addresses on the same port is a duplicate.
- **Standards-only values, no guesses.** VES perf3gpp: what is expected comes from the NF's 3GPP `PerfMetricJob` (`_3gpp-common-measurements`, read with `<get>`, shown read-only on the Monitoring tab): `granularityPeriod` of stream-based jobs; file PM: `fileReportingPeriod` of file-based jobs; else the period the data states (`measDataCollection.granularityPeriod`, file `granPeriod`); else nothing is expected (no 900 s default). PM discovery: a container is PM only when its YANG declares RFC 6991 counter / gauge types (no name matching); units only from YANG `units`; counters only from YANG types (RFC 8343 interface counters without the NF's YANG); list keys from YANG, or where the standard fixes them (3GPP `id`, interfaces `name`), never guessed (CM editing refuses entries without a known key). VES: events are attributed only by `sourceName` / `sourceId` / `reportingEntityName`, never by the sender's IP address; heartbeat expectation only from `heartbeatInterval` or the verified subscription period (no 60 s default). O-RU transceiver results carry no unit (the module defines none as YANG `units`).
- New setting **PM read period when none is given** (`pm_pull_default_s`, 300 s): MiniSMO's own `<get>` schedule for a PM model, replacing a built-in default.
- O-RU PM: the expected interval of `measurement-result-stats` notifications comes from the O-RU's `notification-interval` only (no 900 s default). Without it the source is **NOT_PROVISIONED** (the O-RU sends no periodic notifications), never stale and no notifications; the pull source has no expected interval (the measurement intervals only set how often MiniSMO reads). Fixes the repeated "measurement-result-stats notifications not working … expected every 900 s" notifications.
- **External NF performance view** looks like the simulated one: Managed object and Counter selectors, a tile per counter of the selected object (newest value; counters as rate per second), click a tile to chart it, chart next to the managed-object tree. New API `GET /api/ext-pm/{nf_id}/latest?resource=`.
- **Configuration page reads an external NF only on READ (GET-CONFIG)**: opening the page or selecting an NF no longer runs get-config and the YANG download; the snapshot history and the announced datastores are shown without contacting the NF. Refreshing the page no longer re-reads the selected NF.
- **Lighter MiniSMO** (no feature removed):
  - storage health (every minute, Dashboard, status bar, System Capacity) uses file and folder sizes; the per-table measurement, which reads the whole database (about 1 s per call on an 850 MB database, more on Windows), runs only for the Storage page and is kept 10 minutes. This was the main cause of the database connection pool running out ("QueuePool limit … reached", seen as simulator ticks and VES events failing);
  - SQLite `synchronous=NORMAL` (WAL, crash-safe; no disk flush per commit) and the WAL file is cut back to 64 MB after checkpoints; maintenance returns free pages in steps until none are left, so the database file shrinks after cleanup;
  - NETCONF log written in batches (one transaction per half second instead of one per message); reads flush first; single log entries are read by id instead of loading 5,000;
  - 3GPP AlarmList re-read at most every 5 s (30 s when the NF also reports faults by VES), notifications in between coalesced;
  - alarm events from VES no longer store a second copy of the raw event (the VES event log has it; the alarm history returns it from there);
  - the Windows app does not poll while minimized, never starts a refresh while the previous one is still running, refreshes the status bar every 15 s, and reads external PM tiles / charts every 10 s and the counter list every 30 s (was every 5 s with a full count).
- **External PM tiles** show the counter names exactly as the NF reported them (no upper-casing, wrapped, never cut); only names received from the NF are shown. The freshness line uses the newest stored sample of any source (it said "no samples yet" while VES values were arriving).
- **Lighter again** (measured, no feature removed):
  - external PM storage is compact (schema 22: `ext_pm_series` holds the names once, `ext_pm_values` is a table without rowid keyed by series and time): about 35 bytes per value instead of about 390, and PM intake about 12x faster (23,000 values/s instead of 1,700 on the test machine); existing samples are moved;
  - raw VES events, alarm notifications and configuration snapshots are stored zlib-compressed; dedup hashes are 128-bit (half the size in table and index); a redundant alarm-history index is dropped;
  - VES heartbeats are kept for the NETCONF log retention instead of the FM retention;
  - VES intake keeps the NF/source-name index in memory (rebuilt only when NFs or source names change) and writes the NF's VES state and the event log entry in one transaction: alarm events 200 -> 270/s, heartbeats 255 -> 420/s;
  - the simulator reads its NFs as plain columns, generates live values only when they are looked at or stored, and stores PM with one multi-row insert: 1,000 simulated NFs cost 9 ms a second instead of 57 ms;
  - the backend freezes its start-up objects out of the garbage collector and collects less often; the Windows app uses workstation GC without the background GC thread, polls at a third of the rate while another window is in front, and the Performance page reads only the selected NF's live values;
  - gaps in external PM charts are detected only against the interval the NF stated (no median guess).
- **Capacity assessment, measured operations**: new first profile *Measured Operations Capacity*. It drives MiniSMO's real VES alarm, heartbeat and perf3gpp intake, NETCONF alarm and configuration-change notification handling, NETCONF reads over SSH and API requests in a temporary instance, measures CPU per operation, bytes stored and memory per NETCONF session, and gives the number of external NFs for a stated standard operation per NF (6 alarm events/h, 6 NETCONF notifications/h, 1 heartbeat/min, 500 PM values per 15 min, 6 configuration changes/h, 12 reads/h, 0.6 API requests/min, one NETCONF session), limited by processing (60% of one core), memory or disk with the retention settings. Shown on the System Capacity tab and in the capacity report.
- Fix: the capacity test failed at once on a normal installation ("requires the httpx package"): it drove its temporary instance with a test-only HTTP client. It now serves the temporary instance on a free 127.0.0.1 port with MiniSMO's own HTTP server and measures real HTTP requests. A failed test now says why on the System Capacity tab.
- Build warnings CS0414 (unused fields left from the former Community allowance in Analytics) removed.
- Capacity test: stored bytes per operation are measured from the database's pages in use (the per-table measurement is not available in every SQLite build, which made the disk figures far too low on Windows); *Estimated technical external NF capacity* under License vs System uses the measured operations result; the empty simulated-profile table is hidden when only the measured operations profile ran.
- Network Functions: **Test connection** on a saved NF now shows every stage (✔/✘, detail, duration) in a dialog, like the Add External NF test, instead of a one-line status.
- NETCONF Log: the Operation column is wider and no longer cut off (full name in a tooltip); Duration is shown as "12 ms" / "1.24 s" instead of a raw number.
- Dialogs follow the app theme (they came up light in the dark theme) and use the full dialog width, so stage lists and summaries are no longer cut off.
- NF Monitoring tab: **START MONITORING** is highlighted only while monitoring is off; once it runs it is a normal button (it still re-subscribes).
- Status bar alarm counts are updated from the Alarm Console's and the Dashboard's own reads, so they always show the same numbers.
- License page: **REMOVE LICENSE** is disabled when no license is installed; empty fields show "–"; a license without an expiry shows "No expiration".

A path counts only when the NF advertises it and has it provisioned (PerfMetricJob; o-ran-performance-management enable-file-upload / remote-file-uploads / notification-interval; data arriving). `<get>` is fallback / diagnostic only: on standby (not polled) while a provisioned higher path delivers, with a SPOT CHECK read on request; polled when nothing higher is provisioned or the primary goes stale. Each kept file can be saved to the exports folder or reprocessed without a new retrieval. Copies are cleaned every hour and shown as *Measurement Files (copies)* in the storage breakdown. Schema 23.

The 3GPP NRM has no NF-level state (it is per cell), so an O-DU shows "Not reported by the NF" instead of UNKNOWN; connecting no longer sets an external NF to ENABLED.

- FM: OpenConfig alarms (openconfig-alarms, vendor-neutral, as on Cisco IOS XE) are supported by polling /system/alarms: new entries raise alarms, entries that disappear clear them. The model defines no notification, so it is never offered as a notification path. Labelled as OpenConfig, not as an SDO standard.
- NETCONF: a reply with control characters XML 1.0 forbids (for example a banner's ^C delimiter in an IOS XE configuration) is read with those characters replaced by U+FFFD and a WARNING in the NETCONF Log; before, it was dropped as malformed and the request failed later with "timed out waiting for server response" (CM: "Initial configuration snapshot failed"). A reply that is still not XML fails at once with the parser's reason.
- Monitoring cards no longer show the same explanation twice (detail and warning).
- NETCONF: when an NF's complete <get-config> reply is not well-formed XML (Cisco IOS XE: an unclosed ietf-diffserv-classifier element), the configuration is read part by part with subtree filters; readable parts are kept, the unreadable ones are named (NETCONF Log, CM card, Configuration). A malformed reply no longer drops the session.
- Identity: NFs that implement `openconfig-platform` instead of `ietf-hardware` (for example Cisco IOS XE) get their manufacturer, model (part number), serial number, hardware and software version from the chassis component, so Software Campaigns and Inventory show what the NF reports. Placeholder values such as `NULL` count as not reported; an NF that reports no manufacturer in a standard model is listed as *vendor not reported* (the Cisco DevNet IOS XE sandbox, for example, reports its software version but no manufacturer in `openconfig-platform`).
- Measurement jobs: the measurement names an NF already shows wrap into rows (and scroll down when there are many) instead of scrolling sideways under a scroll bar that covered them; the measurement check lists leave room for their scroll bar.
- **Alarm history**: **HISTORY…** on the Alarm Console searches every stored alarm by date range, text, state and severity, 200 at a time, for as long as FM retention keeps them, also after MiniSMO restarted. It is read only when you select SEARCH. Schema 30 (index).
- Times are shown with their date everywhere (Dashboard, Alarm Console, VES Collector, Monitoring, chart axes, Configuration); time columns are wide enough for date and time. Long values wrap instead of being cut off: measurement job fields (file reporting period), software versions, flapping, audit log actions, system health values (alarm rate), NF types (GENERIC NETCONF NF). The chart legend no longer covers the unit label.
- VES Collector: an NF whose heartbeat is missed shows **Why nothing arrives**, from what the collector observed (TLS failures with their reason, requests, refused senders naming the NF, or no connection at all and where its subscription points); failed TLS handshakes are listed per sender. Times in the VES tables are no longer cut off.
- VES destination kept in place: when an NF loses MiniSMO's VES subscription (configuration reset, another tool), MiniSMO reads its own entry back (after a netconf-config-change that touches it, every 10 minutes while the heartbeat is missed, every 30 minutes otherwise) and writes it again only when it is missing, with a notification.
- Help: **Recently viewed** is a separate card above the contents that can be collapsed (remembered on this PC).

## Known limitations

See the User Guide, *About MiniSMO > Known limitations*. R1 does not provide CAPIF security (per-API OAuth) or CAPIF events, access is by API token; the DME information types are MiniSMO's own; MiniSMO is not a Non-RT RIC and runs no rApps. Secret values in snapshots and logs are recognised by leaf name; a vendor leaf that holds a secret under another name is not masked.
